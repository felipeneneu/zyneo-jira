# Task 29-01-26 — Security + Performance Review

## Findings

### Medium — Reliability/Performance
**Issue:** Cursor pagination without deterministic order may skip or repeat items in bulk actions.  
**Location:** `src/features/notifications/server/route.ts`  
**Details:** `/mark-all-read` and `/remove-all` use `Query.cursorAfter` without a stable order. In Appwrite, cursor pagination relies on deterministic sorting.  
**Fix:** Add `Query.orderDesc("$createdAt")` (or `Query.orderAsc("$id")`) to both loops.

### Medium — Security/Performance
**Issue:** Unbounded `taskIds` payload allows oversized requests.  
**Location:** `src/features/tasks/server/route.ts`  
**Details:** `/report-overview` accepts arbitrarily large arrays, causing heavy DB fan‑out and large prompts.  
**Fix:** Cap length (e.g., `z.array(...).max(500)`) and/or truncate prompt sample.

### Low — Reliability/UX
**Issue:** Friday gating uses client local time while server uses `NODE_ENV` + server time.  
**Location:** `src/features/tasks/components/task-view-switcher.tsx`, `src/features/tasks/server/route.ts`  
**Details:** Users in different timezones can see conflicting availability.  
**Fix:** Add a report‑availability endpoint or use workspace timezone.

## Security Scan Script

## Performance Notes
- Bulk actions run in 100‑item pages and `Promise.all` per page; add deterministic ordering to ensure predictable pagination.
- Report generation remains client‑side (jsPDF). Large task lists may be slow; consider a cap or “top N” option.
